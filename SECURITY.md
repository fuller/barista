# Security

Keep provider keys on the server. Never include them in client code, logs, screenshots, issues or pull requests. Treat recognized text and cart context as data sent to the configured provider during live interpretation.

For a suspected vulnerability, use the hosting platform's private vulnerability reporting feature if enabled. Otherwise contact a repository maintainer privately through an established channel before publishing exploit details. Do not post credentials or personal data. This repository does not yet designate a security email or response-time commitment.

Include affected revision, reproduction steps, impact and a minimal sanitized example. Test only local instances or systems you are authorized to assess. If a credential was exposed, revoke it through its provider and remove the exposure from all published artifacts and history.
